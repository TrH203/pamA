## 1. Nguyên tắc chung

- **Một nguồn sự thật cho mỗi thứ, và luôn hiển thị nguồn gốc.** Mọi giá trị hiệu lực (model,
  key, server) phải trả lời được câu "lấy từ đâu": env, cài đặt đã lưu hay thiết bị.
- **Không có lỗi câm.** Mọi lỗi đều có mã, chặng, nguyên nhân dễ hiểu, cách sửa và nút
  "thử lại".
- **CLI và Web ngang nhau.** Làm được gì trên web thì cũng làm được bằng CLI (`--json`), và ngược lại.
- **Từ vựng thống nhất** (mục 2), dùng chung cho CLI, web, desktop và docs.
- **Giữ nguyên các quyết định cũ:** không có chat bot theo nền tảng; transcript thô không rời
  máy; digest lưu bằng tiếng Anh; review thủ công là mặc định.

## 2. Từ vựng mới (đề xuất)

## 3. Spec 005: Quản trị kết nối (Connections)

Mục tiêu: một developer mới cài pamA có thể chọn nơi lưu dữ liệu, model và agent trong vòng
5 phút. Họ chuyển qua lại giữa local và cloud, đổi provider hoặc key mà không phải đọc code, và
luôn thấy cấu hình đang hiệu lực.

### 3.1 Mô hình "Connection profile"

Gom toàn bộ trạng thái kết nối của máy vào một mô hình duy nhất, lưu trong `device.db`:

```
profile
  home: local | server(url)          // thay cho mode + sync.default_target + remote.servers
  servers[]: {url, device_id, label, logged_in_at, token_ref}
  models: {chat, small, embed}       // mỗi role: provider, model, base_url, key_ref, origin
  agents[]: {id, enabled, scope: global|projects[], hook_installed, transcript_dir}
  privacy: {strict_offline, declared_hosts}
```

- Đặt `pama status` (mới) làm màn hình tổng: máy đang dùng server nào, model nào (kèm nguồn gốc),
  agent nào đang bật, lần capture gần nhất, và tình trạng sync.
- Hợp nhất `pair` vào `login` để thành **`pama connect <url>`**. `pair` vẫn chạy được, nhưng chỉ
  là bí danh in ra cảnh báo deprecated.
- Thêm `pama server list | use <url> | forget <url>` để đổi server mà không phải đăng nhập lại.
- Thêm `pama use local | pama use <url>` để chuyển nơi lưu dữ liệu. Lệnh hiển thị trước điều gì sẽ
  xảy ra (dữ liệu nào ở lại, dữ liệu nào cần sync) và yêu cầu xác nhận.

### 3.2 Model và key

- **Registry provider dùng chung:** `packages/types/providers.json` liệt kê các provider:
  - Ollama, LM Studio, vLLM
  - OpenAI, Anthropic, OpenRouter, DeepInfra
  - "OpenAI-compatible tuỳ chỉnh"

  Mỗi provider khai báo URL mặc định, role hỗ trợ, có cần key không, local hay cloud, và vài model
  gợi ý. Cả Rust và TS cùng đọc file này, nên logic `is_local` cũng dùng chung.
- **Thứ tự ưu tiên rõ ràng:** cài đặt đã lưu > env > mặc định. API `/v1/models/effective` trả về
  từng role kèm `origin`. Web và CLI đều hiển thị nhãn "từ env", "đã lưu" hoặc "thiết bị".
- **Tách hai phạm vi model:**
  - **Model của server** (trả lời, embed, phân loại).
  - **Model soạn digest trên máy** (khi lưu trên server).

  Hai phạm vi có hai thẻ riêng trên UI. Không dùng chung key `provider.chat.*` cho hai nghĩa như
  hiện nay.
- **Key:**
  - `--key-stdin` ở mọi lệnh, không bao giờ nhận key qua argv.
  - `pama keys list` liệt kê provider nào đã có key (không in ra giá trị), lưu ở đâu, kiểm tra
    lần cuối khi nào.
  - `pama keys test <provider>`.
  - Trên web, ô nhập key chỉ ghi vào, có nút "Kiểm tra".
- **Kiểm tra sức khoẻ:** `pama model check` và `pama doctor` kiểm đủ 3 role trên server hiệu lực,
  đi qua egress guard, và báo lỗi theo mã (mục 4.2).
- `model setup` có thêm role small, và có wizard chọn preset: "Hoàn toàn offline (Ollama)",
  "OpenRouter một key", "OpenAI", "Anthropic + DeepInfra embed".

### 3.3 Agent (Claude Code, Codex và các agent sau này)

- Tạo một **adapter trait** trong `pama-core` (`AgentAdapter`) gồm:
  - `id`, `display_name`
  - `default_transcript_dirs`, `parse(path)`
  - `install_hook(scope)`, `uninstall_hook`, `hook_status`
  - `idle_delay`

  Đăng ký adapter trong một registry. Phía server, `AgentSchema` và check constraint đọc danh
  sách từ registry dùng chung. Thêm một agent mới khi đó chỉ cần một file adapter và test.
- Lệnh mới:
  - `pama agents` để liệt kê: phát hiện được không, hook đã cài chưa, scope, số session gần đây.
  - `pama agents enable <id> [--global|--project .]`, `pama agents disable <id>`
  - `pama agents uninstall` để gỡ hook sạch sẽ; hiện tại chưa có lệnh "un-init".
  - Bật/tắt theo từng agent; hiện chỉ có một danh sách dùng chung.
- Codex: cài theo đúng scope. Khi đã có notifier khác thì cho phép chain thay vì từ chối.
- `doctor` phát hiện được hook cài với `--project-scope`.
- Adapter tiếp theo (đã chốt): **Cursor** và **OpenCode**. Cần khảo sát định dạng transcript và
  cơ chế hook của từng công cụ trước khi viết spec.

### 3.4 UI: trang "Kết nối" (Settings → Connections)

Có bốn thẻ, mỗi thẻ có chấm trạng thái (xanh, vàng, đỏ) và hành động trực tiếp:

1. **Nơi lưu dữ liệu:** máy này hay server, danh sách server, nút đổi, nút đăng xuất.
2. **Model:** 3 role của server và model soạn digest trên máy. Mỗi role có provider, model, nhãn
   nguồn gốc, thời điểm kiểm tra cuối, nút "Kiểm tra" và "Đổi". Khi đổi, hiện cảnh báo dữ liệu
   rời máy và cảnh báo cần reindex (đã có gate, giờ đưa lên UI rõ ràng).
3. **Agent:** Claude Code và Codex, mỗi agent có công tắc, scope và trạng thái hook.
4. **Thiết bị:** các máy đã kết nối (`/v1/devices`), lần thấy cuối, nút thu hồi, nút tạo mã ghép.
   Phần này thay cho trang "Devices" mà docs đang nhắc tới.

Ngoài ra:
- Desktop phải biết remote mode: background loop, sidecar và `set_sync` đều đi theo `home`.
- Cửa sổ Settings của desktop chỉ còn các mục riêng của desktop (hotkey, nguồn trả lời); phần còn
  lại mở trang Connections.

## 4. Spec 006: Quan sát pipeline digest

Mục tiêu: lúc nào người dùng cũng trả lời được ba câu: session vừa xong đang ở đâu, nó có lỗi
không, và lỗi vì sao, sửa thế nào.

### 4.1 Mô hình "run"

- **Máy:** giữ bảng `captured_session` và thêm bảng `capture_attempt`, mỗi lần thử là một dòng gồm
  stage, started/ended, error_code, error_detail, provider, role, model và duration. Lịch sử không
  bị xoá khi re-enqueue.
- **Server:** thêm bảng `digest_runs` (id, session, stage, status, error_code, ...). Chuyển
  `/v1/transcripts/digest` sang dạng bất đồng bộ: trả về `202 {run_id}` rồi xử lý qua queue đã có
  sẵn (in-process cho PGlite, pg-boss cho Postgres). Việc này bỏ được timeout 30s và tình trạng
  sinh digest trùng.
- Các chặng chuẩn, hiển thị như một timeline:
  `detected → parsed → redacted → drafted → classified → embedded → ready_for_review → approved → synced`
  Trạng thái `skipped` luôn kèm lý do.
- Sau khi có digest, ghi `digest_id` ngược về máy để biết capture đã thực sự xong và đã publish.

### 4.2 Bảng mã lỗi

`provider_unreachable`, `provider_auth`, `rate_limited`, `timeout`, `invalid_model_output`,
`transcript_missing`, `transcript_too_large`, `empty_session`, `project_not_enabled`,
`sync_not_enabled`, `not_logged_in`, `server_down`, `sync_rejected`, `internal`.

- Mỗi mã có thông điệp cho người dùng, gợi ý sửa (kèm lệnh cụ thể), và có thể thử lại hay không.
- Server không trả `internal error` cho lỗi provider nữa; nó trả mã kèm role và provider. Ví dụ:
  "Embed (ollama, bge-m3) không kết nối được 127.0.0.1:11434. Hãy chạy `ollama serve` hoặc đổi
  provider embed."
- **Chính sách retry:** backoff dài hơn (1 phút → 5 phút → 30 phút → 2 giờ, tối đa 24 giờ) thay vì
  5 lần trong khoảng 1 phút. Lỗi cấu hình (auth, chưa bật) thì dừng ngay và chờ người dùng.
- Kiểm tra trước khi gọi LLM: session rỗng hoặc quá ngắn thì `skipped: empty_session`, không gọi
  LLM.
- Khi embed lỗi, giữ lại bản nháp đã sinh để retry chỉ chạy lại từ chặng embed.

### 4.3 Nơi hiển thị

- **CLI**
  - `pama status`: khối "Pipeline" gồm số đang chạy, chờ review và lỗi, kèm lỗi gần nhất.
  - `pama activity [--failed] [--follow]`: danh sách capture với timeline từng chặng. `--follow`
    stream trực tiếp.
  - `pama activity show <id>` và `pama activity retry <id|--all-failed>`.
  - `pama logs [--server] [--follow]`.
  - Hook vẫn im lặng, nhưng `pama scan` và `drain` khi chạy tay có spinner và tiến độ.
- **Web**
  - **Trang chủ mới (Home)** thay cho Review làm trang mặc định. Trang có thẻ pipeline (đang chạy,
    lỗi, chờ duyệt), các vấn đề cần xử lý kèm nút sửa, và hoạt động gần đây.
  - **Trang Activity:** bảng run với bộ lọc, mở chi tiết thì thấy timeline từng chặng, lỗi, và các
    nút "Thử lại", "Mở log" và "Sửa cấu hình".
  - Cập nhật trực tiếp qua **SSE** (`/v1/events`), không còn polling 30 giây.
  - Empty state của Review cho biết trạng thái thật, ví dụ "2 session đang được soạn" hoặc "1
    session lỗi: xem".
  - Badge đếm số mục trên menu: Review, Inbox, Activity (lỗi).
- **Desktop:** gửi thông báo hệ điều hành khi có lỗi cấu hình, gom lại để không spam. Biểu tượng
  tray đổi trạng thái khi có lỗi.
- Doctor gộp vào Activity và Connections. `pama doctor` vẫn giữ để chẩn đoán và in báo cáo.

## 5. Spec 007: Sync local ↔ online

### 5.1 Quyết định kiến trúc (đã chốt: Publish)

Hiện có hai đường sync:
- **Local mode cộng bản sao cloud:** chỉ đẩy một chiều digest đã duyệt.
- **Remote mode (thin client):** đẩy bản nháp lên, rồi kéo quyết định review về.

**Đề xuất:** giữ một mô hình duy nhất. Máy soạn digest, còn "home" quyết định nơi review, link và
trả lời. Có thể là server local hoặc server từ xa.

- Đổi tên tính năng "bản sao cloud" ở local mode thành **Publish**: đẩy những task đã duyệt lên một
  server công khai để Ask Link chạy khi máy tắt. Ghi rõ là một chiều, và sửa đổi trên server đó
  không quay về máy.
- Hoặc bỏ hẳn tính năng này, khuyến nghị dùng remote mode cho ai cần chạy online.

### 5.2 Việc cần làm (dù chọn phương án nào)

- Thêm `pama sync now` và nút "Đồng bộ ngay". Tự sync khi approve trên console.
- **Trang Sync** trên web và khối Sync trong `pama status`, gồm:
  - project hay task nào đang sync, đi tới server nào
  - lần sync cuối
  - hàng đợi
  - các mục bị từ chối (`dead`), có `last_error`, nút thử lại và nút bỏ
- Cảnh báo khi đã kết nối mà chưa bật sync project nào ("Đã kết nối nhưng chưa có gì được gửi
  lên"). Đây chính là trạng thái của cloud hiện giờ.
- Khi `pama connect` xong, hỏi luôn những project nào sẽ sync.
- Remote mode:
  - gửi tên bundle
  - hỗ trợ bật/tắt sync theo task (FR-012 của spec 004)
- Sync được cả cấu trúc chia/gộp task, bằng cách triển khai kiểu outbox `BundleChange`.
- Khi tắt sync sẽ làm Ask Link mất phạm vi, phải cảnh báo trước và liệt kê các link bị ảnh hưởng.
- Đổi server mặc định thì hỏi có chuyển các project cũ sang server mới không.

## 6. Spec 008: Conversation, session và thư viện

Phần này chỉ lên plan trước, triển khai sau 005–007.

### 6.1 Conversation cho Ask Link

- Bảng mới `conversations` (id, link_id, visitor_id, title, created_at, last_at, status). Thêm cột
  `asks.conversation_id`.
- **Hỏi tiếp có ngữ cảnh:** `answerQuestion` nhận N lượt gần nhất của hội thoại (giới hạn token).
  Guard Layer 3 vẫn áp dụng cho từng câu trả lời, và ngữ cảnh không được làm phạm vi link rộng hơn.
  Cần thêm eval red-team cho kiểu tấn công nhiều lượt.
- **Phía người hỏi:**
  - nút "Cuộc trò chuyện mới"
  - danh sách hội thoại của mình
  - nếu đã xác minh email, mở lại lịch sử trên thiết bị khác qua OTP
  - tự xoá lịch sử của mình
- **Phía owner (trang Conversations):** danh sách theo link và theo người hỏi. Mở một hội thoại để
  xem từng câu, câu trả lời, trích dẫn và trạng thái (đã trả lời, từ chối, chuyển tiếp). Owner trả
  lời ngay trong luồng. Inbox trở thành một bộ lọc ("cần owner trả lời") của trang này.
- Thời gian lưu giữ: cấu hình được (hiện cứng 180 ngày). Owner xoá được từng hội thoại, xuất được
  CSV hoặc JSON.

### 6.2 "Hỏi agent của tôi" (owner)

- Trang **Chat** trong console: owner chat với agent của chính mình trên toàn bộ dữ liệu, hoặc một
  phạm vi tự chọn. Tính năng này dùng cùng pipeline trả lời và có lịch sử theo phiên.
- Từ một phiên chat, owner có nút "Tạo Ask Link từ phạm vi này".
- Popup hotkey trên desktop lưu lịch sử bản nháp (các bản gần đây) và mở lại được.

### 6.3 Thư viện (Library): Project → Task → Agent session → Digest

- API mới:
  - `/v1/sessions` (list và detail)
  - `/v1/digests?status=approved|draft|...`
  - `/v1/search?q=` (full-text cộng vector trên digest items)
- Web: trang **Library** dạng cây hoặc cột. Chi tiết một session gồm agent, thời gian, branch,
  trạng thái capture, các phiên bản digest và nhật ký thay đổi. Hành động gồm withdraw, xoá, chuyển
  sang task khác, và mở các link đang dùng session này.
- Trang Bundles hiện tại gộp vào Library, thành phần "Task", gồm đổi tên, gộp, tách và giải thích
  ngắn "Task là gì".
- CLI:
  - `pama tasks list|rename|merge|split`
  - `pama sessions list|show`
  - `pama digests list|show`
  - `pama search`

  Các lệnh nhận cả tên lẫn id, không bắt người dùng đi tìm id trong `sync status`.
- Review dùng **trình sửa có cấu trúc** (goal, decisions, outcome, open items theo từng trường),
  không còn textarea JSON.

## 7. Spec 009: Thiết kế lại UI/UX

### 7.1 Hướng thẩm mỹ

Hiện đại, mềm mại, tối giản. **Không dùng gradient.**

- **Màu:** nền trung tính hơi ấm (stone hoặc sand), một màu nhấn duy nhất có độ bão hoà thấp:
  **sage** (xanh lá xám). Có ba màu ngữ nghĩa: success, warning và danger, mỗi màu có
  bản nhạt dùng cho nền pill. Trạng thái không bao giờ chỉ dựa vào màu; luôn có icon và chữ đi kèm.
- **Hình khối:** bo góc 10–14 px cho card, 8 px cho control. Viền 1 px nhạt thay cho bóng đậm, bóng
  rất mềm chỉ dùng cho popover và modal.
- **Chữ:** Inter hoặc Geist cho UI, JetBrains Mono cho mã và id. Thang chữ cố định (12/13/14/16/20/24).
- **Khoảng cách:** lưới 4 px, mật độ thoáng. Tối đa 2 cấp nhấn mạnh trên một màn hình.
- **Dark mode** ngay từ đầu, bằng token CSS variables trong Tailwind v4 (`@theme`).
- **Chuyển động:** nhẹ, 120–200 ms, tôn trọng `prefers-reduced-motion`.

### 7.2 Nền tảng kỹ thuật

- **Router:** TanStack Router (có type-safe và hỗ trợ deep-link). URL đổi theo trang, nút back hoạt
  động.
- **Data:** TanStack Query, để có trạng thái loading/error/refetch thống nhất và nhận cập nhật từ SSE.
- **Component:**
  - Radix primitives cộng bộ component của dự án trong `packages/ui`, theo kiểu shadcn: copy vào
    repo, sở hữu code.
  - Gồm Button, Input, Select, Switch, Tabs, Dialog, Toast, Tooltip, Table, Badge/StatusPill,
    EmptyState, Skeleton, Card, Field, CommandPalette.
- **Icon:** lucide-react.
- **i18n:** VI/EN cho cả console, desktop và Ask page (dùng chung `packages/i18n`), đặt `lang`
  đúng theo ngôn ngữ.
- **A11y:** role/aria cho tab và dialog, focus ring rõ ràng, contrast AA, điều khiển được hoàn toàn
  bằng bàn phím. Có `Cmd+K` command palette.
- **Responsive:** console dùng được trên tablet. Ask page ưu tiên mobile vì người hỏi thường dùng
  điện thoại.

### 7.3 Kiến trúc thông tin (console)

Sidebar trái, thu gọn được:

```
Home              trạng thái tổng + việc cần làm
Review      (3)   digest chờ duyệt (trình sửa có cấu trúc)
Conversations (2) hội thoại Ask Link (Inbox = bộ lọc)
Links             Ask Link + tạo link (wizard 3 bước)
Chat              hỏi agent của tôi
Library           Project → Task → Session → Digest, tìm kiếm
Activity    (!)   pipeline runs, sync, audit log
Settings          Connections · Privacy · Retention · Account
```

### 7.4 CLI

- Màu với `anstream` và `owo-colors`, tôn trọng `NO_COLOR` và tự tắt khi không phải TTY. Bảng với
  `comfy-table`. Spinner và tiến độ với `indicatif`.
- Bố cục output thống nhất gồm tiêu đề, khối key–value và bảng. Lỗi theo dạng
  `✗ <mã>: <nguyên nhân>` kèm `→ <cách sửa>`.
- Mọi lệnh đều có `--json` với schema ổn định để làm tích hợp.
- `pama` không có tham số thì in ra `pama status` cùng gợi ý bước tiếp theo.

### 7.5 Desktop

- Popup: dùng cùng design system, có lịch sử bản nháp và chọn phạm vi bằng combobox có tìm kiếm.
- Tray: chấm trạng thái (ổn, đang soạn, có lỗi) và mục "Mở Activity".
